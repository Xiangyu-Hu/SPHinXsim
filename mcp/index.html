    Connect an external agent through MCP

    Build/install the native project following the installation guide. On Linux and macOS, install the extras from the same checkout:

    python -m pip install '.[mcp,cad,results,visualization]'
sphinxsim capabilities --json

    On Windows, use the CI-tested installation described in the Windows guide instead of installing cad. Without CadQuery, CAD modeling is unavailable; install the results extra separately if headless result export or quality checks are needed.

    Configure an MCP client with the installed native CLI, for example:

    {
  "mcpServers": {
    "sphinxsim": {
      "command": "/path/to/venv/bin/sphinxsim",
      "args": ["mcp", "--root", "/workspace"]
    }
  }
}

    The server uses the official SDK and stdio transport. It requires no product account, cloud gateway or proprietary handshake. The process owner selects the workspace and supplies resource isolation. Do not expose unrestricted workspaces.

    Discover the running inventory instead of copying a stale schema. capabilities reports source evidence and limitations; compile returns a new configuration; validate checks an explicit config_file; project_inspect returns the resource inventory; submit requires that reviewed project inventory. Use submission_id for retries. geometry defaults to a persistent CAD job. All job operations take the returned complete reference object, including its request hash.

    A native desktop is optional. Start it with sphinxsim desktop serve ... and give its owner-only reference file to sphinxsim mcp --root ... --desktop-reference .... Only then is desktop advertised. Observe status, then send the explicit instance/version and operation scope; the server never silently fetches a fresh version to make a stale edit succeed. Remote computer-use drivers are external.

    Verified artifacts use sphinxsim://jobs/{job_id}/artifacts/{name} resources. Reads are limited to published files and 1 MiB per resource; use owner-provided file delivery for large assets. Resource access rechecks published size/hash evidence.

    Read the native workflow guide for CLI examples, JSON contracts, execution lifecycle, quality interpretation and test boundaries.

    The Agent and Chatbot use this same stdio service through the official MCP SDK. Tool discovery includes the following authoring and analysis operations.

    Operation Input and result
    templates List verified 2D and 3D reference simulation templates
    template_init Initialize a workspace configuration and referenced STL/data assets from a template
    config_read Read raw text and validation diagnostics of a workspace configuration (even if broken JSON) or template
    config_generate Generate validated native JSON into an explicit workspace file
    config_update Update and validate a selected configuration before saving
    config_patch Apply a validated UpdatePatch, replacement config, or instruction to config.json (with .bak backup)
    config_restore Atomically restore config.json from its .bak backup (swapping current contents for redo)
    config_propose Return a validated draft proposal and admission report
    search_docs Search offline SPHinXsim documentation, tutorials, tool contracts, and templates by keyword
    case_prepare Copy a configuration and stage its STL/data resources
    set_friction_angle Update one plastic-continuum body using degrees
    job_wait Wait up to timeout_seconds for a job to reach a terminal or waiting state (returning logs on failure)
    results_summary Summarize VTP frames, .dat observer/energy series, quality checks, and optional VTK or Blender Cycles renders/scene bundles (renderer, color_by, frame, samples, fluid_surface, save_bundle, save_blend)
    analyze_result Evaluate a runout or declarative analysis plan
    compare_results Compare completed measurements with a target
    results_render Render a PNG (via VTK or Blender Cycles) or export a portable Cycles scene bundle from verified published geometry and particles

    These tools use the same snake_case names, JSON Schema input validation, structured object results, workspace paths, and MCP error responses as the native operations. submit and the job operations support Windows and POSIX. Generated case resources are copied into content-addressed files under the working project. Result analysis checks the job's complete reference, frozen input inventory, and published asset hashes before reading particle data.

    When launched by Workbench, its connection enables a workbench tool for draft status, revision-bound proposals, and workflow observation. Discover this tool from the running server. Apply and save proposals through the desktop editor. The Chatbot accepts /mcp <tool> <JSON arguments> for explicit calls, including with a mock provider. For example, /mcp capabilities {} queries the native inventory. Real LLM providers also select discovered tools through structured requests and receive the actual operation results before answering.

    The optional skill guides experimental decisions; install it through your client's supported skill mechanism. It grants no access.

    No Docker image is required by this protocol. Image names, GPU devices, remote desktop servers, browser embedding and authentication are deployment choices outside this repository's agent implementation.
